A small language for
building things.

Plain text files. No build step. No toolchain to configure before your first program runs. Write .zng in any editor and run it with one command. 

class Dog {
    let name
    func new(name) { self.name = name }
    func speak() { return self.name + " says woof" }
}

print(new Dog("Rex").speak())
$ zing run dog.zng Rex says woof
Install Packages Read the guide

Packages

Install a library from the terminal, then use it by name.

Install

zing install mathx

Installed into ~/.zing/packages. Add --upgrade to update, zing list to see what you have.

Use

import mathx print(mathx.mean([1, 2, 3]))

A package is a folder of .zng files with a zing.json manifest, so you can also install straight from a folder.

Publish

zing publish

Uploads the package to the registry. The registry is self-hosted and standard-library only — tools/registry_server.py.

Install

Linux & macOS

One command. No sudo, nothing outside your home directory.

curl -fsSL https://jaivardhanpandey66-create.github.io/zing/install.sh | sh

Puts zing in ~/.local/bin. Add --with-associate to register .zng files with your desktop.

Windows

Paste one line into PowerShell. It downloads the runtime and the language, then puts zing on your PATH. No administrator rights, nothing installed system-wide.

iwr https://raw.githubusercontent.com/jaivardhanpandey66-create/zing/main/install.ps1 -useb | iex

From a checkout, run powershell -ExecutionPolicy Bypass -File .\install.ps1. Already have Python 3.11? It is used instead of downloading another copy. A single-file installer is produced by packaging/windows/build-installer.sh on Windows with Inno Setup.

Any editor

A VS Code extension adds highlighting, snippets and run/build from the editor. Install the bundled .vsix today, or search zing once it is published to the Marketplace.

code --install-extension zing-0.2.0.vsix

Other editors: point your run command at zing run <file>.

From a checkout

git clone https://github.com/jaivardhanpandey66-create/zing cd zing && ./install.sh --local .

What it looks like

Classes that just work

Fields, methods, one optional constructor called new, and extends for inheritance. Overridden methods dispatch the way you would hope, with nothing to configure.

C++ when you want it

import gpp compiles and runs real C++ from inside a zing program and hands the output back. Results are cached by source hash.

Errors that point somewhere

Syntax errors report a line and column and draw a caret under the problem. An accidental infinite loop stops with a message instead of hanging your editor.

Modern where it counts

Keyword arguments, sets, list and map comprehensions, generators with yield, @decorators, function values and closures, destructuring like let [a, b] = pair, run-time type annotations, a match statement, and regex built in.

Python and C++ when you need them

import py reaches any installed Python module directly — py.module("math").sqrt(2) just works — while import gpp compiles and runs C++. Both are optional; the language itself needs only Python 3.11+.

Compiles to native code

zing build app.zng turns a program into a real native executable with a C compiler (-O3 -march=native). Maps, indexing, slicing, match, list and map comprehensions and more compile natively. A recursive benchmark runs about 8× faster than the interpreter, with no Python in the finished binary.

In your editor

Highlighting, snippets, F5 to run, Ctrl+Shift+B to check, and errors as red squiggles.

  • Syntax highlighting for every token class the language has
  • Snippets for classes, constructors, loops, match, comprehensions, generators and decorators
  • Problems parsed from the CLI, never re-implemented in the extension
  • Run with F5, build a native binary, and zing fmt rewrites the buffer, refusing to if it would change what the program means
